## G1 的具体依赖

逻辑审计以 `LojitaCtx.Posix` 和 `LojitaCtx.Io` 两棵模块树中的声明为根，包含私有声明、自动生成的声明和定理。每个根用 Lean 的 `collectAxioms` 检查，只接受 `propext`、`Classical.choice`、`Quot.sound`。即使标准库原语已有审查记录，传给原语的项目表达式也在检查范围内。

运行时信任清单与 Lean 4.36.0 官方发行版绑定。清单记录声明、模块、原生符号或替换实现和等式证明，以及审查依据。部分实现只允许由清单中的调用方引用。项目读取字节会用到官方 `ByteArray` 的原生表示；磁盘、终端与网络的操作则须经 `CoreCaps` 和宿主解释器。工具链变更需要重新核对清单。发行版指纹、逐项依据和受限调用关系见 [审计目录](../Test/audit/) 和 [固定工具链逐项审查](POSIX_G1_LEAN436_REVIEW.md)。

旧规格的两种计数继续逐项输出，便于比较后续版本。在本轮之前的 `1244b39`，2,953 个根的第一种遍历命中 91 项（77 extern、13 unsafe、1 个编译器公理），再计入 `csimp` 的目标和证明后命中 109 项（91 extern、17 unsafe、1 个编译器公理）。两种数字包含重叠项。原规则把 `InodePayload.reg → ByteArray → ByteArray.mk` 也计作一次 extern；新规则仍报告这条路径，同时检查对应的官方原生符号。编译器内部的 `lcProof` 单列审查，项目逻辑引用它会被拒绝。

此前修复消除了 errno 相等判断对 `Sum.ctorIdx._impl` 的依赖，以及文件描述 ID 分配证明对 `List.attachWithImpl` 的依赖。文件读取用携带边界证明的索引，写入保留稀疏区域的零填充语义。`Test/TheoremPin.lean` 对任意偏移和长度证明新读取与原 `ByteArray.extract` 的字节一致，并从新的 `read_replaced` 导出旧表述。

## T15 的读取状态

旧文件读取路径会在每次读后重建多张平衡树。即使键和值相同，两次与三次读取也可能得到不同树形。现在 `read` 和 `pread` 直接发布读取后的状态，另有 Lean 证明表明引用计数与描述符不变量仍成立。两节点回归会检查真实树形，以便检测这种差异。

## Linux 行为与契约

- T15 直接运行 `runPrefix`。两条调度可以使用不同的读取大小、不同的短读位置和有限次 EINTR。普通文件可从已有偏移甚至 EOF 之后开始。关闭写端的管道同时覆盖已有和缺失的页布局。两侧最终值包括全部 FD、打开文件描述、inode、管道页及其他设备状态。
- 流式 socket 的对端关闭写方向后，已排队的字节可以读完，后续读取持续返回 EOF。在 PTY 上，最后一个 slave 关闭后，master 先读完已排队的输出，再得到 EIO。最后一个 master 关闭后，slave 的待输入数据被清空，读取返回 EOF。规范模式下的空 VEOF 只交付一次。T15 覆盖任意多条已提交记录、跨记录请求造成的提前短读，以及 VEOF 后仍有待交付数据的情况。若对端仍开着且没有更多数据，后续非阻塞读返回 EAGAIN。
- 长度不超过 4,096 字节的管道写入有原子性。仅剩 1 字节空间时，非阻塞写 2 字节得到 EAGAIN。先写满再读走 1 字节也可能仍占用全部页槽。差分覆盖部分读、短写、页尾追加以及 POLLOUT。
- T13 对所有仍有链接的 inode 比较目录结构、模式、链接数、软链目标及文件字节。关闭只读描述符会调整引用计数，最后一次关闭无名文件会回收 inode。
- T16 的成功条件包括成功打开、进展性读取和成功关闭。完成后逐个 FD 检查映射。FD 耗尽直接返回 EMFILE。T14 的两个行片段都不含换行；T15 允许有限次中断，并要求调度最终能读到 EOF 或写完。
- 只读挂载上，以 O_RDONLY | O_CREAT 打开既有文件可成功。创建缺失文件或截断既有文件会返回 EROFS。模型还按 Linux 的错误优先级处理 EEXIST、EBUSY 及管道定位 IO 的 ESPIPE。

## 入口与边界

新入口的类型是 `LojitaCtx.Posix.PosixProg LojitaCtx.Posix.CoreCaps UInt32`。会话可通过 `(build-exe ... (mode posix))` 构建，MCP `check_entry` 的 `mode` 填 `posix`。原有 cli 和 reactive 模式继续服务既有 World 类型的封存入口。兼容层在 Lean 中分派 stdin、TTY、信号和计时事件，底层等待使用同一个 POSIX `ppoll`。静态库中已移除旧 C 事件轮询符号。

纯程序和解释器共用 `LojitaCtx.Io` 缓冲逻辑。宿主侧可信组件包含固定版 Lean 运行时、Linux 内核、libc、原生系统调用桥、静态启动包装、namespace/Landlock 启动器及以 Python 标准库实现的 TreeCAS 磁盘读写。TreeCAS 按字节处理文件名、链接目标与内容，拒绝无法保真表示的硬链接、特殊权限位与特殊节点。运行时保留 Linux 未命名的错误码。差分结论仅覆盖已执行的序列。
