# Ownership.agda 第四版：一个类型化的 shell

> 用 Agda 脚本代替 bash。文件 = 数据 ⊗ 资源；脚本 = 从一棵树到另一棵树的箭头；
> 进程 = 树上一格"子树交出去以后留下的收据"。内核里没有 IO、没有公理；
> 现实世界由 IO 层在需要的时候接到树上。

两个文件：

| 文件 | 是什么 |
|---|---|
| `Ownership.agda` | 内核。类型、命令、脚本、进程、纯模型、定理。纯的：没有 IO，没有 postulate。 |
| `Main.agda` | IO 层。整个仓库里唯一碰外界的地方：字节 ↔ 类型化的值、把岛接上、跑 `eval`。 |

```
检查：agda -i . -i <stdlib路径> Ownership.agda        (Agda 2.6.3, stdlib 1.7.3)
编译：agda --compile --ghc-flag=-iruntime -i . -i <stdlib路径> Main.agda   然后   echo 21 | ./Main   →  42
```

## 0. 先看一眼：一段脚本长什么样

```agda
delegated : Prog (("w" , [] , WorkerS) ∷ []) (Dir []) (Dir []) ℕ
delegated = do
  mkdir "w"
  open′ "w"          -- 把空目录 "w" 交出去，剩一张收据：Chan WorkerS
  create "f" 41
  send "f" "w"       -- 文件 "f" 从我的清单消失，进了信道
  v ← recvD "w"      -- 对面告诉我一个数
  recv "w" "f"       -- 文件回来了，我又叫它 "f"
  close "w"          -- 协议走完，收据作废
  unlink "f"
  done (suc v)
```

类型 `Prog Ψ s s′ A` 读作：**这段脚本用到清单 Ψ 里的外部接口，把形状 s 的树变成形状 s′ 的树，交出一个 A。**
这里 s 和 s′ 都是 `Dir []`（空），所以类型本身就保证：什么都没泄漏，什么都没凭空出现。
`("w" , [] , WorkerS)` 是一条假设："叫 w 的岛，拿到一个空目录，会按协议 WorkerS 行事"。对面是谁？脚本不知道，也不用知道。

## 1. 为什么要它

| Harness 的要求 | 这个文件怎么回应 |
|---|---|
| agent 的权限 = 它持有的文件 | 凭证就是类型里那棵子树。类型里没有的格子，脚本碰不到——不是有人检查，是位置算不出来 |
| 修改 = 删旧造新，带着记忆搬运 | 没有 `write`；修改就是 `unlink` + `create`。一段脚本 = 一个事务 |
| 1 改了 2.test 就唤醒 2，1 只能等 | 父亲对岛只有两个动词：`open′`（交出去）、`recover`（收回来）。中间父亲进不去 |
| 只能预先规划结构，过程不可预期 | 类型只管形状（St）和协议（Session）。谁在对面、会不会停，是 IO 层的事 |

和 bash 的根本差别：bash 脚本是对着一个**未知**的文件系统写的，所以才需要 `ls`、通配符、`[ -f x ]`；
`Prog` 是对着一个**已知形状**的树写的——形状在类型里。不会被文件系统"惊讶"，这不是限制，是省掉了一整类错误。

```

          │   St 形状树        Session 协议        Ψ 假设清单        │
          └─────────────────────────┬────────────────────────────────┘
                                    │ 作为索引
          ┌─────────────────────────▼────────────────────────────────┐
          │   Prog 脚本        Proc 岛上的程序      Server 常驻的岛    │   每段都是有限的证明
          └──────────┬─────────────────────────────────┬─────────────┘
              eval   │                                 │   （调度循环，待写）
          ┌──────────▼──────────────┐      ┌───────────▼──────────────┐
```

同一段脚本有两个解释器：`eval` 把它跑在纯模型上（干跑，能证定理，能跑测试）；IO 层把它翻成真实操作。
两者来自同一个泛性质：对每条命令各说一遍意思，所有脚本的意思就定了。

## 3. 两侧：数据与资源

**数据侧就是 `Set`。** 任何 Agda 类型的值都是数据：ℕ、String、record 都行。复制、丢弃不需要许可（这是 `!` 的 δ 和 ε）。内核不知道也不关心数据的形状；"怎么把字节变成某个类型的值"是 IO 层的事。

```agda
copy : A → A × A
copy a = a , a
```

关键不在数据长什么样，而在数据里**装不着资源**：资源不是值，是类型层的索引。索引没法被装进一个值里再偷运出去。

**资源侧是 `St`，一棵树：**

```
   File A     一个文件，内容类型是 A
   Dir Γ      一个目录；Γ = [(名字 , 状态) , …]
              孩子的状态嵌在父亲的状态里 ←── 这一句就是所有权
   Chan S     一根信道的一端：子树交出去以后留在原位的收据
              格子、位置、名字都在；里面没有文件，只有一张单子 S："对面将来会给我什么"
```

三个故意没有的东西：没有 `Absent`（不存在 = 不在父亲的清单里；`Dir []` 就是"空"，幺半范畴的单位）；
没有 `Open/Closed`（open 只是向运行时领一个读者份额，类型层看不见）；没有 `write`（修改 = 删旧造新）。

## 4. 脚本：三种 cut

一段脚本是一支箭头 `Prog Ψ s s′ A`。它由命令接成，命令是内核答应你的几件事——也就是**工具注册表**：

```
   叶子    read                                        交出一个 A，文件还在（线性侧跨到笛卡尔侧的唯一一步）
   目录    create / unlink / mkdir / rmdir              名字的生与灭；rmdir 只删空目录
   别名    link                                        只对文件：给目录起别名会让线性子树有两个主人
   搬运    up / down                                   叶子一个不多一个不少，只是换位置（mv = up 再 down）
   信道    recv recvD send sendD close recover call stop   见 §5
```

命令接成脚本的方式只有三种，它们是三种 cut，差别只在左边放什么：

```
   step  c κ      左边是公理（一条命令）        走一步。线性就在类型里：出口必须等于下一步的入口
   focus x p κ    左边是证明（一段子脚本）      父亲等：同一个进程、同一段事务。相当于 (cd x && …)
   exec  z h κ    左边是一个洞                  父亲不等：洞的形状 = 假设 h，谁来填是环境的事
```

`focus` 画出来就是张量的函子性——一支箭头下到一格里去再上来，其余格子原样穿过：

```
   孩子的世界      stateOf x ──────p──────▶ s′
                       │                    │
                 id ⊗ (—) ⊗ id        id ⊗ (—) ⊗ id
                       ▼                    ▼
   父亲的世界      Dir Γ ────focus x p───▶ Dir (set x s′)
```

借用、frame 规则、"子函数只能碰传给它的东西"全在这一个构造子里：子脚本的类型里根本没有外面的格子。

**用户只写名字。** 下一步的目录形状由名字层的一阶函数算（`delete n Γ`、`update n s′ Γ`、`lookupSt n Γ`），
前提（"名字在""这是文件""目录是空的""这一格的协议是……"）算成 ⊤ / `x ≡ x` 就由实例自动补上，算成 ⊥ 就是类型错误。
`Raw` 要的位置证明只在包装里由 `member-at` 造出来，三条 coherence 引理（`remove-at` / `set-at` / `stateOf-at`）
说两种算法算的是同一个东西（§3 开头的注释讲了为什么不直接把 `remove (at w)` 写进类型：那样二十步脚本是一座二十层的塔，检查器的内存按指数长）：

```agda
borrowed = do
  create "log" ""
  mkdir "work"
  d ← inside "work" scratch     -- 把 "work" 借给 scratch；借出期间它碰不到 "log"
  rmdir "work"                   -- scratch 的签名承诺：进来空目录，出去空目录
  unlink "log"
  done d
```

## 5. 会话类型：一个命题，两边站

```agda
data Session where
  End : Session                     -- 1      协议走完
  _⊗_ : Ty → Session → Session      -- t ⊗ S  先交出一个 t，再按 S 走
  _⊸_ : Ty → Session → Session      -- t ⊸ S  先收进一个 t，再按 S 走
  Srv : Set → Set → St → Session    -- 常驻服务：问一次答一次、可以无限次；或者关门，交还 s′
```

能传的东西两种，正好对应两侧：`Res r`（一棵子树，线性，送出去就不在我手里了）、`Dat A`（一个值，笛卡尔，送出去手里还有）。

会话类型是线性逻辑的**命题**。命题没有视角：同一个 S，站在右边是"提供它"，站在左边是"使用它"。所以这里**没有 dual**——对偶就是换一边站：

```
   命题 S           右边：提供者（Proc 的构造子）        左边：使用者（Cmd 的信道命令）
   ──────────────────────────────────────────────────────────────────────────────
   End              end     说完了，手里必须空            close    走完才能关 = rmdir 只删空目录
   Res r ⊗ S        give    交出一格，它从我清单消失       recv     收下一格，起个名字   (= up)
   Dat A ⊗ S        tell    交出一个值，手里还有           recvD    收一个值
   Res r ⊸ S        take    收进一格，起个名字             send     交出一格，名字消失   (= down)
   Dat A ⊸ S        ask     收一个值                       sendD    发一个值，手里还有
   Srv Q R s′       daemon  以下无限（余归纳）             call 问一圈 / stop 关门收回 s′
   Res r ⊗ End      ——                                     recover  岛结束，收据原地变回子树
```

`recover` 和 `stop` 是对称的：都是"收据原地变身"。它们和 `recv`+`close` 做的事一样，只是不换位置、不换名字。

## 6. Ψ：假设清单，也就是语境

一条假设 `Spec = (名字 , 子树形状 Γ , 协议 S)`，读作相继式 **Γ ⊢ S**："谁拿到这棵子树，就要兑现这个协议"。
一段脚本的类型里带一张清单 Ψ：它用到哪些外部接口（服务、别的 agent……）。任务开始前定好，任务中不改——这就是你文档里的"语境"。

`exec` 用清单里的一条假设开岛：按名字找（和在目录里找格子完全同一套办法），假设要求的子树形状必须和那一格下面现在的一样，协议从假设上读出来。

```
   父亲          Γ, ["2" : Chan S] ⊢ …        S 是一条假设，1 只对它负责
   孩子          Γ₂ ⊢ S                        2.agent 的 LLM 写出来，agda 单独对着 S 检查
   连接          cut                           运行时发生：IO 层在岛启动时把两个证明接上
```

这就是文档里 2.3 那一步 **A.test × B.test × root ⊢ root.test**，现在字面上就是类型：

```
   root     : Prog [A.spec , B.spec] …                 root 对两条假设负责
   A.agent  : Proc Ψ_A Γ_A S_A                         A 对自己那条负责，用它自己的清单 Ψ_A
   root.test = eval (mockA ∷ mockB ∷ []) root ≡ 预期    假设成立 ⇒ root 满足规约
   连接      = provide A.agent                         把 A 的程序变成"对面看到的行为"
```

假设清单保证了分包不会弱化设计：子节点的合取蕴含父节点，因为父节点的证明从头到尾只用了那几条假设。

## 7. 岛：父亲只有两个动词

岛上的程序是 `Proc Ψ Γ S`：相继式 Γ ⊢ S 的证明，构造子就是 S 的右规则（§5 的中间一列）。
常驻的岛是 `Server`：一个余归纳记录，两个字段 `call` / `stop`，对面挑哪个分支它才算哪个——这正是 `&` 的惰性。
它的每一步是一段有限的脚本；"下一步是什么"被问到才展开。**在 Harness 里，填这个字段的是 LLM。**
所以一个 agent 的一生不是一段脚本，是一串段落加一张接口单；父亲手里只有接口单。

文档里"1 改了 2.test 唤醒 2"，在文件里是例 8 `wake`。看 "2" 这一格的一生：

```
   Dir [code, test]        ← 2 在家，1 可以 focus 进去读写
        │ open′ "2"           2.agent open：格子变成 Chan，1 进不去了
        ▼
   Chan (Dat Spec ⊸ Dat Report ⊗ Res (Dir Home) ⊗ End)
        │ sendD "2" spec      新规约当数据发过去（Dat：父亲手里还有一份）
        ▼
   Chan (Dat Report ⊗ Res (Dir Home) ⊗ End)
        │ recvD "2"           等报告。没信就不醒；信到了才有下一段
        ▼
   Chan (Res (Dir Home) ⊗ End)   还欠我一个家
        │ recover "2"         2.agent close：格子原地变回目录，里面是新代码
        ▼
   Dir [code, test]
```

1 没法指挥 2 中途做什么——类型里没有那条命令。"唤醒"在两边是同一条规则：**一个 agent 可跑，当且仅当它手里的格子允许它走一步。**

## 8. 模型与定理

类型层是名字树；模型层是树上每片叶子里装的东西：

```
   Model (File A)  = A                      一个值
   Model (Dir Γ)   = 孩子们的模型
   Model (Chan S)  = Offer S                对面那个进程剩下的行为：
        Offer (t ⊗ S)   = t × Offer S           对面要交出 t：模型里已经有一个 t 等我拿
        Offer (t ⊸ S)   = t → Offer S           对面要收进 t：模型是个函数，喂它
        Offer (Srv …)   = Running（余归纳）      问多少次都行
```

这就是 cut 在模型里的样子：一根信道的两端，一端是"我手里的收据"，另一端**是对面整个进程**。纯模型里它是一个值；现实里它是一个正在跑的进程、一次 LLM 调用、一个人。

`eval` 多一个参数——环境 `Env Ψ`：清单里每条假设各给一个"拿到子树的模型，吐出对面的行为"。
`exec` 那一行就是开放的 cut：向环境要一个 `Offer`，放进那一格。**eval 不钻进任何孩子**，所以没有什么需要终止。
`provide` 把一个 `Proc` 变成 `Offer`——这是链接：root.test 里用它接模拟接口，IO 层在岛启动时做同一件事。

定理（都是 `refl`，Agda 算出来的）：

| 定理 | 说的是 |
|---|---|
| `get-get` | 读两次 = 读一次再 copy。"快照合法"的依据；不可变世界里 lens 三律只剩这一条 |
| `link-shares` | 硬链接之后，新名字绑的就是旧名字的那个值 |
| `link-data` | 岛只说一句话就结束；收下、关门 ≡ rmdir 后直接拿那个值往下走。**通信 = 代换** |
| `link-res` | 岛收下一格再原样交回；发过去、收回来 ≡ 什么都没发生。**通信 = 搬运** |
| `link-stop` | 开门就关门 ≡ 直接跑服务的 stop 分支 |
| 三个 root.test | `eval (provide [] worker ∷ []) delegated tt ≡ (tt , 42)`；数据库例子答 7；`wake` 跑完家回来了、代码换了、测试没动 |

有些东西不是定理，是类型：
"父亲死前孩子必须全死"是 `rmdir` 的类型；"关门前会话必须走完"是 `close` 的类型；
"整棵树最终全部释放"是 `clear` 的类型；"整个系统会不会停"不是内核的事——对面坐着人和 LLM。

## 9. drop glue

Rust 的 drop 是编译器生成、不检查的；这里它是一个可以证明的程序 `clear`：无论目录里是多深的树，跑完以后目录是空的。顺序被 `rmdir` 的类型逼出来：先孩子后父亲。

前提 `Droppable`：什么能被无条件丢掉？

```
   File、Dir（孩子都能丢）          直接丢
   Chan End                         关门
   Chan (Res r ⊗ End)               先 recover 收回，再丢 r
   Chan (Srv …)                     先 stop 收回 s′，再丢 s′
   其他信道                         不行：欠对面一个值你变不出来；对面还要给你别的东西，你得先收
```

这是会话版的"父亲死前孩子必须先死"：关门前每根会话必须走到 End。

## 10. 写不出来的脚本

文件里注释着九个，取消注释就是类型错误：

| 名字 | 想干什么 | 被拒在哪 |
|---|---|---|
| `leak` | 建个文件就结束 | 终点形状不是 `Dir []`：泄漏 |
| `rmFull` | 删一个非空目录 | `IsEmptyDir` 算成 ⊥ |
| `reachOut` | 借到子目录的脚本去读父目录的文件 | 它的上下文里没有那一格，位置算不出来 |
| `linkDir` | 给目录做硬链接 | `IsFile` 算成 ⊥：名字层必须是树 |
| `unlisted` | 清单是空的还想开岛 | 没有假设说对面有人 |
| `early` | 协议没走完就 close | 前提 `≡ Chan End` 不成立 |
| `dropMid` | 话说到一半 deleteAll 信道 | `Droppable` 算成 ⊥ |
| `peek` | 交出去以后 focus 进去看 | 那一格是 Chan 不是 Dir：盒子不透明 |
| `steal` | 收了一格就 end | `end` 要求手里是空的：收到的东西归你，但得交代去向 |

## 11. 为什么没有层数了

第三版有一个层数 ℓ：`fork` 只能 fork 低一层的进程。它存在的唯一理由是封闭世界的 `fork z q κ` 把孩子的**整个程序** q 装在父亲的项里，`eval` 要钻进 q 去算，于是"钻多深"必须有界，否则一个"每被 call 一次就 fork 一份自己再 call 它"的服务会让 `eval` 不终止。

开放世界里父亲手里根本没有 q——2 的程序在 1 写脚本时还不存在。`exec` 只交出接口；`eval` 向环境要一个现成的 `Offer`，不钻进任何东西。没有东西可钻，也就没有东西需要终止。

```
   封闭世界     整个系统 = 一个项             eval：项 ↦ 结果
   开放世界     整个系统 = 一个带洞的项        eval：(洞里填什么) ↦ 结果
                洞 = 树上的 Chan 格子         洞里的东西 = Offer S，由 IO 在需要时从现实世界取来
```

失去的只有一条：那个自己 fork 自己的服务不再被类型拒绝。但它也不再能被拒绝——它不在类型里。在纯模型里连它的环境都构造不出来（那是一个非 guarded 的递归值）；在现实里它就是一个跑不完的 agent，而"整个系统会不会停"本来就不是内核能承诺的事。

## 12. IO 层：Main.agda

只做三件内核不做的事：

1. **字节 → 类型化的数据。** stdin 的一行解析成一个 ℕ。"怎么把一串字节变成某个类型的值"只在这一层出现；进了内核的数据已经有类型了。
2. **兑现假设。** `pipeline` 的类型说它要一个叫 "srv" 的岛。这里把岛接上：`provide [] (daemon dbServer) ∷ []`。真实世界里这一步是启动一个进程、一次 LLM 调用；这个 demo 的岛也是 Agda 写的，所以直接 `provide`。
3. **跑 `eval`，把结果变回字节打印。**

IO 单子来自标准库；它底下的 FFI 是标准库的事，本仓库一条公理也不加。
